# Sources of the review tooling

The files in this directory and at the repository root are derived partly from published, permissively licensed work.
This note records what came from where, so a later reader can tell a borrowed rule from a rule this project decided.

| Our file | Upstream source | Licence | What was reused |
|---|---|---|---|
| `../REVIEW.md`, `.claude/skills/review-pr/SKILL.md` | [`anthropics/claude-plugins-official`](https://github.com/anthropics/claude-plugins-official) → `plugins/code-review` (Apache-2.0, Copyright Anthropic PBC) | Apache-2.0 | The definition of a high-signal finding, the false-positive list ("pre-existing", "appears to be a bug but is actually correct", "linter-catchable", "general code quality" — adapted), the verify-before-posting step, and the rule that a committable suggestion is offered only when it fixes the issue completely. The plugin's diff-only restriction and its "stop if Claude has already commented" rule were **deliberately rejected**: both were measured failing on this repository (see `V2-D85`). |
| `../REVIEW.md`, `.claude/skills/review-pr/SKILL.md` | [`amd/gaia`](https://github.com/amd/gaia) → `REVIEW.md` (MIT, Copyright 2024-2025 Advanced Micro Devices) | MIT | The sibling-path check ("a change that lands on one path while a sibling stays broken"), the documentation-drift check (search the *old* wording, not the file the PR already touched), the length and nit caps, the re-review rule ("stricter, and silent on nits"), the severity-applies-to-documents idea, and the shape of a severity table. Every example and every rule's content is this project's own. |
| `../REVIEW.md`, `.claude/skills/review-pr/SKILL.md`, `.github/workflows/claude-code-review.yml` | [`anthropics/claude-code-action`](https://github.com/anthropics/claude-code-action) → its `CLAUDE.md`, its review command and review workflow, and its security and usage documentation (MIT) | MIT | The base-branch checkout pattern for a ref the action does not own, the strict-permission-mode plus allow-list and deny-list shape for a review job, and the structure of a short project guide ("What this is", "How it runs", "Things that will bite you") used in `../custom-memory-engine/CLAUDE.md`. The reviewer subagents (`security-code-reviewer` et al.) were **not** reused: they are generic OWASP checklists whose "when uncertain, flag it" instruction produces the false positives `PLAN/CONTRIBUTING.md` §1.1 asks the reviewer to avoid. |
| `../REVIEW.md` | [Customize Code Review](https://code.claude.com/docs/en/code-review-customize), [Code Review](https://code.claude.com/docs/en/code-review), [Set up Code Review](https://code.claude.com/docs/en/code-review-setup), [Read and request reviews](https://code.claude.com/docs/en/code-review-pull-requests), [Code Review costs](https://code.claude.com/docs/en/code-review-costs) (Anthropic documentation) | Documentation, quoted and paraphrased | The mechanically relevant facts, not text: `REVIEW.md` is read from the protected base/default branch and `CLAUDE.md` from the root plus each changed file's parents; subdirectory `REVIEW.md` files require a *ruleset*; `@`-includes need the root file on a protected branch; the 8-file / 150,000-byte / 30,000-byte-skill / 64-link limits; the severity names (Important / Nit / Pre-existing); the review levels and what drives cost; and that a review never approves or blocks. |

Nothing above is vendored: no upstream file is copied whole, and the Apache-2.0 and MIT texts are not redistributed
because no substantial portion of either work is included. Where a sentence is close to its source it is attributed in
this table and in the docs that cite it (`PLAN/V2/DECISIONS_V2.md` `V2-D85`).

Everything else — the authority order, the invariants, the threat-model rows, the migration rules, the closure protocol,
the evidence bar's six parts as applied here, the severity calibration for engine changes, and every script and test —
is this project's own and is governed by the repository's `LICENSE`.
