# [RL-026] Freeze development vs. test splits for all suites (`Gate J5`)

**Milestone:** `P2 Benchmarks and own suites`  
**Labels:** `enhancement`  
**Proposed Owner:** Member 4 (`R-DB`) · **Peer Reviewer:** Member 1 (`R-LEAD`)

## Objective & Why
Deterministically partition every dataset (`LongMemEval`, `LoCoMo`, and synthetic suites `T`, `G`, `D`, `I`) into disjoint development and test splits (`Graduation_Project_Proposal.md` §§10.2, 10.7) and sign `FREEZE_LIST.md` (`Gate J5`) before any pilot or experiment runs.

## Scope & Deliverables
- **In Scope:**
  - `LongMemEval`: Stratified split by question type with fixed seed (~20% development, ~80% test per `Proposal` §10.2).
  - Own suites (`T`, `G`, `D`, `I`): Scenario-level split assigned by deterministic SHA-256 hash of `scenario_id` so no scenario ever appears in both splits.
  - `LoCoMo`: Conversation-level split recorded for descriptive reporting.
  - Signed `research-lab/research/benchmarks/splits/FREEZE_LIST.md` recording split counts, seeds, and file SHA-256 hashes.
- **Out of Scope:**
  - Running any baseline or engine configuration on the splits (`RL-100`–`RL-105`).
- **Deliverables:**
  - `research-lab/research/benchmarks/splits/{longmemeval,locomo,own_T,own_G,own_D,own_I}.yaml`
  - `research-lab/research/benchmarks/splits/FREEZE_LIST.md`
  - Split-disjointness verification test.

## Acceptance Criteria
- [ ] Automated test verifies zero overlap (`dev ∩ test = ∅`) at the cluster level (`question_id` for `LongMemEval`, `scenario_id` for `T`/`G`/`D`/`I`, `conversation_id` for `LoCoMo`).
- [ ] Split assignment is 100% deterministic from the recorded seed.
- [ ] `FREEZE_LIST.md` is signed by Member 4 and reviewed by Member 1 (`Gate J5` in `TRACEABILITY_MATRIX.md` §5).
