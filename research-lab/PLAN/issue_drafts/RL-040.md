# [RL-040] Full-schema DDL

**Labels:** `rl:kind/task`, `rl:phase/P4`, `rl:area/engine`, `rl:status/proposed`, `rl:dep/blocking`, `rl:effort/L`, `rl:risk/high`
**Milestone:** `P4 Schema and engine core`
**Phase final deliverable:** `D-P4`.
**Proposed owner:** Member 4 (R-DB).

## Objective
Author the full-schema DDL for the memory engine per proposal §8 and [`../../TECHNICAL_SPECIFICATION.md`](../../TECHNICAL_SPECIFICATION.md) §3.

## Scope
- `MEMORY`, `MEMORY_VERSION`, `PREDICATE`, `MEMORY_EVIDENCE`, `MEMORY_DERIVATION`, `DELETION_LOG`, `JOB`, audit tables.
- CHECK constraints for R1–R8 staging/open-range rules.
- Exclusion constraint with `btree_gist` for single-valued predicates on both ranges (invariant 4).
- Per-user partition keys (§3.2 architectural MUST).
- `recorded_from` monotonicity trigger (R3).

## Out of scope
- Transactional procedures (supersession, archival, deletion). Owned by `RL-042`.
- Retrieval predicates. Owned by `RL-043`.
- Migrations. Owned by `RL-041`.

## Deliverables
- `research-lab/implementation/schema/*.sql`
- `research-lab/implementation/schema/README.md` with an invariants-matrix table showing enforcement site per invariant.

## Acceptance criteria
- [ ] Schema diff vs proposal §8 recorded.
- [ ] Full-schema SQL runs cleanly against the pinned PG version in CI.
- [ ] The reduced-schema V2 SQL assertions (`validation/bitemporal_checks.sql`) still pass against the full schema.
- [ ] Every invariant 1–10 has a declared enforcement site.

## Risk
**High** — the schema is the backbone of every subsequent task.
