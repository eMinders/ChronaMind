# [RL-005] Author `.github/workflows/research-lab.yaml` CI workflow

**Milestone:** `P0 Repository, environment, and CI`  
**Labels:** `enhancement`  
**Proposed Owner:** Member 5 (`R-APP`) · **Peer Reviewer:** Member 1 (`R-LEAD`)

## Objective & Why
Set up the dedicated GitHub Actions CI pipeline (`.github/workflows/research-lab.yaml`, permitted under `D-LAB-CI` in `PLAN/INDEPENDENCE_BOUNDARY.md` §4) to automatically verify documentation integrity, Clopper–Pearson bounds, reduced-schema PostgreSQL assertions, static types, and unit tests on every Research Lab push or PR.

## Scope & Deliverables
- **In Scope:**
  - Trigger on `push` and `pull_request` touching `research-lab/**` or `.github/workflows/research-lab.yaml`.
  - Provision the pinned PostgreSQL + `pgvector` service container from `RL-004`.
  - Run:
    1. `python3 validation/mechanical_checks.py Graduation_Project_Proposal.md Methodology_and_Consistency_Checklist.md CHANGELOG.md`
    2. `diff <(python3 validation/cp_bounds.py) validation/cp_bounds.output.txt`
    3. `psql -v ON_ERROR_STOP=1 -f validation/bitemporal_checks.sql`
    4. `uv run ruff check .`, `uv run pyright`, and `uv run pytest` (from `RL-003` / `RL-006`).
- **Out of Scope:**
  - Modifying the root application workflow `.github/workflows/ci.yaml`.
- **Deliverables:**
  - `.github/workflows/research-lab.yaml`

## Acceptance Criteria
- [ ] Workflow triggers only on `research-lab/**` (and its own workflow file) changes.
- [ ] All four verification steps pass in GitHub Actions.
- [ ] Root `.github/workflows/ci.yaml` is untouched.
