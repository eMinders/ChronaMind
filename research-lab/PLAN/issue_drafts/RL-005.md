## Objective
Add a Research Lab CI job that runs `ruff`, `pyright`, `pytest`, `check_independence.py`, and `validation/mechanical_checks.py` on changes under `research-lab/`.

## Scope
Create dedicated `.github/workflows/research-lab.yaml`, filtered on `research-lab/**` and its own workflow path. Use the independent frozen uv lock and local battery from CONTRIBUTING.md §7. Do not modify main-app CI.

- Use the PostgreSQL/pgvector target selected by RL-012 for future DB checks, pinned tag/digest; no automatic PostgreSQL 16 default. Service can be omitted only while no DB tests exist, with that limitation explicit.
- Empty scaffold pytest exit 5 is recorded as no tests collected, not green test evidence; do not ignore other exits.
- Cache `uv` to speed up builds.
- Fail the job if `check_independence.py` reports a violation.
- Fail the job if `validation/mechanical_checks.py` does not end with `SUMMARY: ALL HARD CHECKS PASSED`.

## Out of scope
- Changing any main-app CI job behaviour.
- Enabling branch protection; that is a repository-admin task.
- Adding deployment jobs for the Lab.

## Deliverables
- Minimal, scoped change to `.github/workflows/`:
  - **Pending scoped exception:** boundary §4 currently permits adding a Lab job to existing CI, not a dedicated workflow file. Follow boundary §5's supervisor-approved exception process before creating `.github/workflows/research-lab.yaml`; D-LAB-CI selection and RL-001 review do not prove this approval.
- Green run on an initial no-op branch under `research-lab/`.

- [ ] CI run on the initialisation PR is green on the Research Lab job.

- [ ] The PR diff touches only the specifically approved `.github/workflows/research-lab.yaml` and `research-lab/`; the guard rejects every other out-of-Lab path.
