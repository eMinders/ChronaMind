# [RL-011] Design and schedule the pilot

**Labels:** `rl:kind/task`, `rl:phase/P1`, `rl:area/experiments`, `rl:status/proposed`, `rl:dep/blocking`, `rl:effort/M`, `rl:risk/medium`
**Milestone:** `P1 Resolve open decisions`
**Phase final deliverable:** `D-P1`.
**Proposed owner:** Member 3 (R-METHOD).
**Covers decisions:** `D-10`, `D-11`, `D-12`, `D-13`, `D-14`, `D-18`, `D-21`, `D-22` (per [`DECISIONS_REGISTER.md`](../DECISIONS_REGISTER.md)).

## Objective
Produce a pilot plan that fixes every value whose resolution is "Pilot" in the open-decisions register, running on the **development split only**.

## Scope
- Write `research-lab/PLAN/pilot_plan.md` describing:
  - What is measured per decision (δ_pres, δ (LUAR), u*, positive-control detection share, suite T stratum mix, exclusion-constraint behaviour under concurrent writers, Graphiti feasibility, judge agreement criterion).
  - Which configurations run (P, A2, A3, A5, A6, A8, B0 at minimum; plus B4 Graphiti if feasibility test passes).
  - Which suites are used (own suites T, D, G at smoke sizes; LongMemEval development split for judge validation).
  - The cost envelope (per `D-20`) and the exit criteria for each measured value.
- Define development-evidence and supervisor-agreement procedures for each freeze criterion; do not adopt an arbitrary u* formula or numeric margin from this draft. Final values require development evidence and signed RL-100 freeze.
- Define owners and target dates per measured value.

## Out of scope
- Running the pilot. That is `RL-100`.
- Finalising the LongMemEval subset. Owned by `D-20` under `RL-010`.

## Deliverables
- `research-lab/PLAN/pilot_plan.md`.
- Updated rows in [`DECISIONS_REGISTER.md`](../DECISIONS_REGISTER.md) with owners and target dates.

## Acceptance criteria
- [ ] Every pilot-owned decision in `DECISIONS_REGISTER.md` has a dated row with owner, target date, pass criterion.
- [ ] Pilot plan explicitly reaffirms the "development split only" rule from proposal §10.7.
- [ ] Supervisor acknowledgement attached (comment on the issue or signed memo under `supervisor_signoff/`).

## Dependencies
**Blocks:** `RL-100`.
**Blocked by:** `RL-010` (needs frozen scope).
**Non-blocking links:** `RL-020`, `RL-030` (data/interface awareness); implementation readiness of adapters/baselines/judge is checked at RL-100. RL-011 procedure acceptance must not wait for RL-033, which depends on this plan.
**Dependency class:** Blocking.
**Can start now?** Not yet. `RL-010` is a blocking prerequisite; its decision preparation may proceed now, but RL-011 pilot procedures wait for accepted RL-010. RL-020/RL-030 are non-blocking context only.
