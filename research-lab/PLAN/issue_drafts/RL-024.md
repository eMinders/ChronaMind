# [RL-024] Own Suite `T` (temporal-change) generator

**Milestone:** `P2 Benchmarks and own suites`  
**Labels:** `enhancement`  
**Proposed Owner:** Member 3 (`R-METHOD`) · **Peer Reviewer:** Member 4 (`R-DB`)

## Objective & Why
Build the deterministic script-first generator for Suite `T` (`Graduation_Project_Proposal.md` §§7.4, 10.2, 10.3) to evaluate `H1` (`P − A2` across the co-primary `history-dependent` and `present-state` strata, plus `A1` `P-flat` diagnostics and deterministic `audit_as_of` checks).

## Scope & Deliverables
- **In Scope:**
  - Multi-session user histories exhibiting single-valued updates, same-day corrections (`R2`), retroactive timing revisions (`E1`–`E3` pattern in `Proposal` §7.4), delayed reports, uncertain start times (`valid_from_basis = 'inferred'`), and multi-valued endings (`R7`).
  - Five conversational question modes: `current`, `as_of` (in current or past period), `what_changed`, `before_change`, and `stable` (unchanged control).
  - Mechanical stratum assignment rule (`Proposal` §10.2):
    - **`history-dependent` stratum:** gold answer requires a non-currently-valid version (`as_of` earlier period, `before_change`, `what_changed`).
    - **`present-state` stratum:** gold answer is derivable from currently valid versions (`current`, `stable`, `as_of` inside current period).
  - Scripted `(valid_time, belief_time)` grid per scenario for deterministic API-level `audit_as_of` verification (`Proposal` §10.3).
- **Out of Scope:**
  - Running `H1` (`RL-101`).
- **Deliverables:**
  - `research-lab/research/benchmarks/own_T/{generator.py,MANIFEST.txt,README.md}`
  - Reproducibility unit tests and stratum-balance checks.

## Acceptance Criteria
- [ ] Every scenario contains both `history-dependent` and `present-state` questions with mechanically derived gold answers and validity intervals.
- [ ] Includes old-value `as_of` questions and `stable` questions so a naive "always return latest" or "always return previous" heuristic fails.
- [ ] Deterministic output for a fixed seed.
