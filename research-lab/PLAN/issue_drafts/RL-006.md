# [RL-006] Publish GitHub Issues, labels, milestones, Project fields

**Labels:** `rl:kind/task`, `rl:phase/P0`, `rl:area/infrastructure`, `rl:status/proposed`, `rl:dep/review-gate`, `rl:effort/M`, `rl:risk/medium`
**Milestone:** `P0 Repository baseline`
**Phase final deliverable:** `D-P0`.
**Proposed owner:** Member 6 is the publication operator; publication requires separate explicit owner authorization and is not authorized by RL-001 acceptance.

## Objective
Publish the backlog as real GitHub Issues, apply labels and milestones per [`GITHUB_SETUP.md`](../GITHUB_SETUP.md), create the Project board, and wire native issue dependencies.

## Scope
1. Create labels listed in `GITHUB_SETUP.md` §1.
2. Create milestones listed in `GITHUB_SETUP.md` §2.
3. Create the Project board with the fields and views listed in `GITHUB_SETUP.md` §3.
4. For every draft under `PLAN/issue_drafts/RL-*.md` and `D-*` entries, create a corresponding GitHub Issue. Title, body, labels, milestone, and the proposed owner field come from the draft. Owner usernames come from the confirmed `ASSIGNMENTS.md` once identities are provided; until then the issue stays unassigned with the role shape in the body.
5. Set GitHub-native `blocks` / `blocked by` relationships per [`DEPENDENCY_MAP.md`](../DEPENDENCY_MAP.md). Where native support is missing, keep the text-level `Depends on:` / `Blocks:` block in the issue body.
6. Add the two issue-template wrappers under `.github/ISSUE_TEMPLATE/` (`research_lab_task.md`, `research_lab_decision.md`) that pass through to the Lab templates. **Allowed exception** per `INDEPENDENCE_BOUNDARY.md` §3.5.
7. Add the pull-request template wrapper at `.github/PULL_REQUEST_TEMPLATE/research_lab.md`.
8. Update [`PROJECT_STATUS.md`](../PROJECT_STATUS.md) with the issue URLs.

## Out of scope
- Automation that assigns, closes, or re-opens issues without human action.
- Changing branch-protection, repository settings, webhooks, or any main-app CI.
- Creating issues for tasks whose draft is not under `PLAN/issue_drafts/`.
